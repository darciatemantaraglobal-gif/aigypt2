Halo, ada tiga perbaikan di project AIGYPT ini. Jangan ubah UI atau desain sama sekali, dan jangan pernah jalanin drizzle-kit push, generate, atau migrate karena schema Drizzle di repo ini sudah tidak sinkron dengan database produksi dan perintah itu bisa merusak data.

Pertama, buka file artifacts/aigypt/api/admin/[...path].ts. Di blok route MEMBERS: CREATE, tiga operasi tulis ke database (insert ke access_codes, insert ke orders, lalu upsertMember) dijalankan berurutan tanpa transaction. Kalau salah satu gagal, dua yang sebelumnya tetap tersimpan dan meninggalkan kode akses nyangkut plus order palsu berstatus paid di database. Bungkus ketiga operasi itu ke dalam satu transaction pakai sql.begin dari library postgres, sehingga kalau ada yang gagal semuanya ikut rollback dan database tetap bersih. Ubah juga fungsi upsertMember supaya bisa menerima koneksi transaction sebagai parameter, bukan selalu memakai koneksi global sql, supaya dia ikut ke dalam transaction yang sama. Lakukan hal yang sama untuk route ORDERS: CREATE dan ORDERS: MARK PAID yang punya pola tulis berurutan serupa.

Kedua, di file yang sama, blok catch paling bawah menelan semua error database dan membalas pesan generik "Terjadi kesalahan server", sehingga saat ada masalah seperti kolom yang belum ada, error aslinya tidak pernah terlihat dari browser. Karena semua route ini sudah di belakang session guard admin, ubah blok catch itu supaya selain tetap console.error, dia juga mengirim balik pesan error asli dari Postgres di field terpisah, misalnya res.status(500).json({ error: "Terjadi kesalahan server", detail: err instanceof Error ? err.message : String(err) }). Lalu di frontend artifacts/aigypt/src/pages/admin/members.tsx, di AddMemberModal dan EditMemberModal, saat respons tidak ok tampilkan detail itu di bawah pesan error utama dengan font mono ukuran kecil warna abu supaya admin langsung tahu penyebab teknisnya tanpa harus buka Vercel logs.

Ketiga, samakan schema Drizzle di lib/db/src/schema/aigypt.ts dengan struktur database yang sebenarnya, murni sebagai dokumentasi tanpa menjalankan migrasi apapun. Tambahkan kolom username bertipe varchar panjang 50 yang nullable ke membersTable, karena kolom itu memang sudah ada di database dan sudah dipakai oleh API tapi belum tercatat di schema. Lalu di ordersTable, ganti definisi grossAmount yang saat ini menunjuk ke kolom gross_amount menjadi menunjuk ke kolom amount, karena seluruh raw SQL di produksi memakai nama kolom amount dan definisi gross_amount itu salah. Tambahkan komentar singkat di atas kedua tabel itu yang mengingatkan bahwa schema ini hanya dokumentasi dan semua perubahan struktur dilakukan manual lewat Supabase SQL Editor.

Setelah selesai, jangan deploy apapun, cukup pastikan tsc lolos tanpa error dan laporkan file mana saja yang berubah.

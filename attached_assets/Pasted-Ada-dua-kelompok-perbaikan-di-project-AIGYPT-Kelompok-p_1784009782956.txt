Ada dua kelompok perbaikan di project AIGYPT. Kelompok pertama adalah bug kritis yang bikin seluruh admin panel mati, kerjakan ini dulu. Kelompok kedua perbaikan tipe TypeScript. Jangan ubah struktur database dan jangan sentuh halaman publik.

KELOMPOK PERTAMA: BUG ROUTING ADMIN PANEL

File yang diperbaiki: artifacts/aigypt/api/_lib/route.ts, pada fungsi getSegments.

Gejalanya begini. Endpoint admin yang cuma punya satu segmen path seperti /api/admin/login dan /api/admin/verify berjalan normal. Tapi semua endpoint yang punya dua segmen atau lebih, seperti /api/admin/codes/list, /api/admin/codes/generate, /api/admin/members/list, dan /api/admin/orders/list, semuanya mengembalikan 404 dengan pesan "Route tidak ditemukan" yang berasal dari fallback di dalam handler itu sendiri.

Akar masalahnya ada pada interaksi antara vercel.json dan getSegments. Di vercel.json ada rewrite dengan source "/api/admin/:path*" dan destination "/api/admin/[...path]". Destination itu tidak ikut menangkap parameter :path*, sehingga Vercel meneruskan sisa path sebagai satu query param bernama path yang isinya string utuh berisi garis miring, misalnya "codes/list", bukan array ["codes", "list"] seperti yang diasumsikan kode. Sementara itu getSegments hanya melakukan concat terhadap nilai tersebut tanpa pernah memecahnya di garis miring, lalu langsung mengembalikannya. Akibatnya variabel section di handler bernilai "codes/list" dan sub1 bernilai undefined, sehingga tidak ada satu pun blok kondisi route yang cocok dan eksekusi jatuh ke 404 di baris terakhir.

Perbaiki getSegments supaya tahan terhadap kedua bentuk. Setelah mengambil nilai req.query["path"], normalkan dulu menjadi array, lalu pecah setiap elemennya berdasarkan karakter garis miring dan gabungkan hasilnya menjadi satu array datar, baru buang elemen yang kosong. Penting: nilai yang datang dari req.query sudah otomatis di-decode oleh Vercel, jadi jangan panggil decodeURIComponent lagi pada jalur ini karena berisiko double decode. Kalau setelah proses itu arraynya masih kosong, biarkan fallback yang sudah ada, yaitu yang memparse langsung dari req.url, tetap berjalan seperti sekarang termasuk pemanggilan decodeURIComponent di dalamnya, karena jalur itu memang menerima nilai mentah yang belum di-decode. Jangan hapus fallback tersebut.

Perbarui juga komentar dokumentasi di atas fungsi getSegments supaya menjelaskan masalah baru ini, yaitu bahwa req.query["path"] bisa datang dalam bentuk string tunggal berisi garis miring akibat rewrite di vercel.json, bukan hanya dalam bentuk array atau kosong. Jangan ubah fungsi getBody dan getQuery. Jangan ubah vercel.json sama sekali, perbaikan di getSegments ini sengaja dibuat supaya aman baik dengan maupun tanpa rewrite tersebut.

KELOMPOK KEDUA: PERBAIKAN TYPESCRIPT

File yang diperbaiki: artifacts/aigypt/api/admin/[...path].ts.

Pertama, fungsi upsertMember punya parameter tx yang dideklarasikan bertipe "typeof sql", padahal yang dilempar ke situ dari dalam sql.begin() adalah objek TransactionSql, yang tidak punya semua properti milik Sql seperti CLOSE, END, PostgresError, dan options. Perbaiki dengan menambahkan import type postgres dari "postgres" tepat di bawah baris import getSegments, getBody, getQuery dari "../_lib/route.js", lalu deklarasikan type alias bernama Executor yang isinya union antara "typeof sql" dan "postgres.TransactionSql", dengan komentar singkat dalam bahasa Indonesia bahwa type ini bisa dipakai baik oleh koneksi biasa maupun transaction. Setelah itu ubah signature upsertMember, ganti parameter "tx: typeof sql = sql" menjadi "tx: Executor = sql". Isi fungsinya tidak berubah.

Kedua, di route ORDERS: CREATE, di dalam blok if (isPaid), variabel accessCode dideklarasikan sebagai "let accessCode: string | null = null". Meskipun sudah ada guard yang mengembalikan 500 kalau nilainya kosong, TypeScript kehilangan penyempitan tipenya begitu variabel itu dipakai di dalam closure "async (tx) => {}" milik sql.begin, sehingga upsertMember menerima string | null padahal butuh string. Perbaiki dengan menyalin nilainya ke konstanta baru tepat setelah baris guard, yaitu "const code: string = accessCode;", lalu di dalam sql.begin ganti semua pemakaian accessCode menjadi code, yaitu pada parameter INSERT INTO access_codes, pada parameter INSERT INTO orders, dan pada properti yang dilempar ke upsertMember yang ditulis sebagai "accessCode: code". Variabel accessCode yang di luar sql.begin tetap dipakai apa adanya untuk res.json di akhir route.

Ketiga, di route ORDERS: MARK PAID pada cabang "if (existingCode)". Cabang ini memakai kode akses yang sudah menempel di order tanpa memastikan kode itu punya baris di tabel access_codes. Karena members.access_code punya foreign key ke access_codes.code, kalau kode itu ternyata tidak ada di sana, upsertMember akan gagal dengan foreign key violation dan mengembalikan 500. Tambal dengan menyisipkan satu query INSERT sebagai query paling pertama di dalam sql.begin cabang tersebut, sebelum UPDATE orders. Query itu memasukkan existingCode ke access_codes dengan kolom code, type, batch_number, dan is_used, di mana type diambil dari order["member_type"], batch_number dari order["batch_number"], dan is_used diisi false, lalu diakhiri dengan ON CONFLICT (code) DO NOTHING supaya idempoten. Sisa isi cabang itu tidak berubah.

VERIFIKASI

Setelah semua selesai, jalankan npx tsc --noEmit terhadap artifacts/aigypt/api/tsconfig.json dan pastikan hasilnya nol error. Jangan menambah dependency baru, jangan mengubah tsconfig, dan jangan menyentuh file di luar dua file yang disebutkan.

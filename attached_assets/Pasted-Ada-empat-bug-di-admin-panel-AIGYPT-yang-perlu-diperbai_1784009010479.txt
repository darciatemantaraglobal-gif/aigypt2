Ada empat bug di admin panel AIGYPT yang perlu diperbaiki. Semua ada di artifacts/aigypt. Jangan ubah struktur database, migration SQL-nya sudah dijalankan manual di Supabase. Jangan sentuh halaman publik, cuma admin panel.

Bug pertama ada di artifacts/aigypt/api/admin/[...path].ts pada route MEMBERS: UPDATE. Route ini menulis ke tiga tabel berturut-turut tanpa dibungkus transaction, padahal route MEMBERS: CREATE di file yang sama sudah pakai sql.begin(). Akibatnya kalau salah satu query di tengah gagal, perubahan yang sudah terlanjur ditulis ke access_codes tidak ikut dibatalkan, dan member jadi menunjuk kode akses yang statusnya keliru ditandai belum terpakai. Bungkus seluruh rangkaian penulisan di route ini ke dalam satu sql.begin(async (tx) => { ... }) dan ganti semua pemanggilan sql di dalamnya menjadi tx. Urutan di dalam transaction harus begini: pertama insert kode akses baru ke access_codes kalau kode itu belum ada di sana, karena members.access_code punya foreign key ke access_codes.code sehingga kodenya harus eksis dulu. Kedua, update baris members. Ketiga, bebaskan kode lama dengan set is_used false, used_by_email null, used_at null, lalu tandai kode baru dengan is_used true, used_by_email diisi email baru, used_at NOW(). Keempat, sinkronkan tabel orders. Semua validasi yang mengembalikan status 400 (email bentrok, username bentrok, kode akses sudah dipakai member lain) tetap dilakukan sebelum transaction dimulai, bukan di dalamnya. Selain itu, hapus baris UPDATE materi_progress SET member_email di route ini, karena foreign key materi_progress_member_email_fkey sekarang sudah ON UPDATE CASCADE sehingga Postgres yang menangani sendiri perpindahan email tersebut.

Bug kedua ada di route ORDERS: CREATE pada file yang sama. Form Catat Pesanan Manual di frontend mengirim status "pending", tapi backend menyimpannya sebagai 'pending_qris'. Padahal dropdown filter di halaman Pesanan mengirim query status=pending, sehingga pesanan yang baru dicatat tidak pernah muncul saat difilter. Perbaiki dengan menyimpan status persis sesuai yang dikirim frontend: kalau status yang dikirim adalah "paid" simpan 'paid', selain itu simpan 'pending'. Jangan pernah menulis 'pending_qris' dari route admin ini. Status 'pending_qris' tetap dipakai oleh flow QRIS publik dan baris lama yang sudah ada di database, jadi jangan hapus dukungannya di query listing maupun dashboard-stats.

Bug ketiga ada di route ORDERS: MARK PAID pada file yang sama. Saat ini route selalu men-generate kode akses baru, bahkan ketika kolom access_code pada order tersebut sudah terisi dari flow lain. Kode lama jadi yatim dan member berpotensi punya dua kode aktif. Perbaiki supaya route mengecek dulu: kalau order sudah punya access_code yang tidak kosong, pakai kode itu apa adanya, jangan generate yang baru, cukup update status order jadi 'paid', set paid_at NOW(), dan jalankan upsertMember dengan kode tersebut. Generate kode baru hanya kalau access_code-nya benar-benar kosong.

Bug keempat ada di artifacts/aigypt/src/components/admin/StatusBadge.tsx. Objek CONFIGS tidak punya entri untuk 'pending_qris', sehingga badge menampilkan string mentah "pending_qris" untuk pesanan lama. Tambahkan entri pending_qris dengan label "Menunggu QRIS" memakai warna amber yang sama persis dengan entri pending yang sudah ada.

Terakhir, dua perbaikan kecil. Di artifacts/aigypt/src/pages/admin/codes.tsx, state batchNum defaultnya masih 1 padahal program sekarang sudah Batch 3, ganti nilai awalnya jadi 3. Lalu di codes.tsx dan artifacts/aigypt/src/pages/admin/members.tsx, input pencarian memicu satu request ke API setiap kali satu huruf diketik. Tambahkan debounce 400 milidetik pada nilai search sebelum dipakai memanggil API, dengan cara menyimpan nilai ter-debounce di state terpisah lewat useEffect dan setTimeout, lalu jadikan state ter-debounce itu yang masuk ke dependency array fetch, bukan nilai input mentahnya.

Setelah selesai, pastikan tidak ada error TypeScript dan build Vite tetap lolos.

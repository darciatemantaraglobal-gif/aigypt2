Ada empat perbaikan kecil di project AIGYPT, semuanya di satu file: artifacts/aigypt/api/admin/[...path].ts. Jangan ubah file lain, jangan sentuh struktur database, dan jangan ubah logika route manapun selain yang gue sebutkan di bawah. Ini murni perbaikan tipe TypeScript plus satu penambalan foreign key.

Perbaikan pertama. File ini punya tiga error TypeScript yang selama ini lolos karena Vercel cuma men-transpile folder api dengan esbuild tanpa typecheck. Akar masalahnya ada di fungsi upsertMember: parameter tx-nya dideklarasikan bertipe "typeof sql", padahal yang dilempar ke situ dari dalam sql.begin() adalah objek TransactionSql, yang tidak punya semua properti milik Sql (CLOSE, END, PostgresError, options, dan lainnya). Perbaiki dengan membuat satu type alias yang menerima keduanya. Tepat di bawah baris import getSegments, getBody, getQuery dari "../_lib/route.js", tambahkan import type postgres dari "postgres", lalu deklarasikan type alias bernama Executor yang isinya union antara "typeof sql" dan "postgres.TransactionSql". Beri komentar singkat dalam bahasa Indonesia bahwa type ini bisa dipakai baik oleh koneksi biasa maupun transaction. Setelah itu ubah signature upsertMember, ganti parameter "tx: typeof sql = sql" menjadi "tx: Executor = sql". Jangan ubah isi fungsinya sama sekali.

Perbaikan kedua. Masih di file yang sama, di route ORDERS: CREATE, di dalam blok if (isPaid). Variabel accessCode di situ dideklarasikan sebagai "let accessCode: string | null = null", dan meskipun sudah ada guard yang mengembalikan 500 kalau nilainya masih kosong, TypeScript kehilangan penyempitan tipenya begitu variabel itu dipakai di dalam closure "async (tx) => {}" milik sql.begin. Akibatnya upsertMember menerima string | null padahal butuh string. Perbaiki dengan menyalin nilainya ke konstanta baru tepat setelah baris guard tersebut, yaitu "const code: string = accessCode;", lalu di dalam sql.begin ganti semua pemakaian accessCode menjadi code. Itu berlaku untuk tiga tempat: parameter pada INSERT INTO access_codes, parameter pada INSERT INTO orders, dan properti accessCode yang dilempar ke upsertMember (tulis sebagai "accessCode: code"). Variabel accessCode yang di luar sql.begin tetap dipakai apa adanya untuk nilai balik res.json di akhir route, jangan diubah.

Perbaikan ketiga. Masih di file yang sama, di route ORDERS: MARK PAID, pada cabang "if (existingCode)". Cabang ini memakai kode akses yang sudah menempel di order tanpa memasukkannya ke tabel access_codes. Masalahnya, upsertMember menulis ke members.access_code yang punya foreign key ke access_codes.code, jadi kalau kode itu ternyata tidak punya baris di access_codes (misalnya karena pernah diisi manual lewat Supabase SQL Editor), transaksinya akan gagal dengan foreign key violation dan mengembalikan 500. Tambal dengan menyisipkan satu query INSERT sebagai query paling pertama di dalam sql.begin cabang tersebut, sebelum UPDATE orders. Query itu memasukkan existingCode ke tabel access_codes dengan kolom code, type, batch_number, dan is_used, di mana type diambil dari order["member_type"], batch_number dari order["batch_number"], dan is_used diisi false, lalu diakhiri dengan ON CONFLICT (code) DO NOTHING supaya idempoten dan tidak menimpa baris yang sudah ada. Sisa isi cabang itu, yaitu UPDATE orders dan upsertMember, tidak berubah.

Perbaikan keempat, terakhir. Setelah semua di atas selesai, jalankan npx tsc --noEmit terhadap artifacts/aigypt/api/tsconfig.json dan pastikan hasilnya benar-benar nol error. Kalau masih ada error tersisa, perbaiki dulu sampai bersih sebelum melapor selesai. Jangan menambah dependency baru, jangan mengubah tsconfig, dan jangan menyentuh file lain.
